# Phase 11.2: True Streaming ASR - Research

**Researched:** 2026-04-19
**Domain:** Continuous ASR Streaming, Neural Engine Optimization, Serial Interleaving
**Confidence:** HIGH

## Summary

This phase shifts the transcription architecture from file-based chunks (5-30s) to high-frequency continuous audio streaming (< 1s). By utilizing the native streaming capabilities of WhisperKit 0.12.0 and FluidAudio 0.10.0, we will achieve sub-second latency for live transcription. The core of the implementation relies on a "Serial Interleaving" pattern where small fragments (200-400ms) from multiple audio sources (Mic and System) are processed by a single `TranscriptionQueue` to ensure Neural Engine stability while providing immediate feedback.

**Primary recommendation:** Use `WhisperKit.transcribe(audioArray:)` with a **Sliding Window (3-5s)** and `FluidAudio.StreamingEouAsrManager` for Parakeet.

## Architecture Patterns

### High-Frequency Serial Interleaving
1. **Source Slicing:** `DualChannelAudioCapture` delivers 10ms-100ms buffers. `MeetingRecorder` accumulates these into 200-400ms "fragments".
2. **Priority Enqueueing:** Fragments are sent to `TranscriptionQueue`. Microphone fragments are prioritized to ensure instant feedback (< 800ms latency).
3. **Session Processing:** The queue calls the appropriate `VoiceToTextProtocol` implementation using a *persistent session* and sliding window.

### SimulStreaming Strategy (SOTA 2025)
1. **LocalAgreement / LCP Policy (n=2):** For every new fragment, perform a re-decode of the current rolling buffer (3-5s). Compare the output with the previous iteration (offset by ~500ms). Only "commit" (display as stable) the **Longest Common Prefix (LCP)** where both outputs match perfectly. This eliminates "hallucination flicker" at the end of sentences.
2. **Sliding Window Policy:** Instead of resetting the buffer, use a 3-5s FIFO sliding window. New fragments are appended, and oldest samples are evicted to maintain context for LCP.
3. **Forced Prefix & Context Prompting:** 
    - Use already committed text as a prefix to maintain sentence flow.
    - **Context Injection (DEFERRED):** Injecting meeting title or keywords is deferred to Phase 13+.
4. **KV-Cache Isolation:** Maintain separate `decoderState` objects for Mic and System streams within the same `AsrManager` instance to avoid context mixing while sharing model weights.
5. **Last-Word Truncation (Anti-Flicker):** Implemented in the `VoiceToTextModel` adapter. If the final word of a fragment doesn't end with a space or punctuation, it is likely partial. Hide it from the `MeetingSegment` text update until the next iteration confirms it.
6. **Adaptive VAD Gating (DEFERRED):** Suspending calls during silence for power saving is deferred to Phase 13+.

### Backpressure Pattern: Drop Oldest
To prevent lag accumulation:
- Monitor `TranscriptionQueue.pendingCount`.
- If total duration of queued fragments > 2.0 seconds:
  - Discard the oldest fragments for the lagging source.
  - Log a warning about Neural Engine congestion.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Token Stitching | Manual append | LCP Policy + Forced Prefix | Prevents hallucinations and flickering. |
| VAD Silence | Custom RMS check | `StreamingEouAsrManager.eouDetected` | Parakeet EOU signals `VADStateMachine` to close segments. |
| Neural Engine Locking| Custom Semaphore | `TranscriptionQueue` (Actor) | Actors are the standard Swift concurrency primitive for serialization. |

## Common Pitfalls

### Pitfall 1: AudioStreamTranscriber Hijack
**What goes wrong:** Attempting to use `AudioStreamTranscriber` requires hijacking its internal `AudioProcessor` which is tied to `AVAudioEngine`.
**How to avoid:** **REJECTED.** Use `transcribe(audioArray:)` directly with a manual sliding window in `VoiceToTextModel`.

### Pitfall 2: Context Break on Reset
**What goes wrong:** Resetting the audio buffer every 5s breaks the LCP logic and causes flickering at boundaries.
**How to avoid:** Use a **Sliding Window** (FIFO) to keep the last 3-5s of audio always available for the next decode.

### Pitfall 3: EOU vs VAD Conflict
**What goes wrong:** Parakeet's EOU and the app's VAD fighting to close a segment.
**How to avoid:** **EOU Priority.** Parakeet EOU detection should be treated as a "Finalize" signal to the `VADStateMachine`.

## Code Examples

### WhisperKit: Sliding Window Manual Feed
```swift
// Implemented in VoiceToTextModel.swift
var slidingBuffer: [Float] = [] // Max 5.0s
var lastTranscription: String = ""

func process(fragment: [Float]) async {
    slidingBuffer.append(contentsOf: fragment)
    if slidingBuffer.count > sampleRate * 5 {
        slidingBuffer.removeFirst(fragment.count) // Simple eviction
    }
    
    let result = try await whisperKit.transcribe(audioArray: slidingBuffer)
    let currentLCP = calculateLCP(result.text, lastTranscription)
    let truncated = applyTruncation(currentLCP)
    
    lastTranscription = result.text
    updateSegment(truncated)
}
```

### FluidAudio: EOU Gated Finalization
```swift
// Parakeet EOU detection signals VAD closure
for try await transcription in manager.transcriptionProgressStream {
    if transcription.eouDetected {
        await vadStateMachine.forceSilence() // Signals closure
    }
    onToken(transcription.text)
}
```

# Phase 11.2: True Streaming ASR - Context

**Gathered:** 2026-04-19
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase implements "True Streaming" ASR token delivery. The primary goal is to minimize the latency between spoken words and their appearance in the UI to the absolute minimum (< 1s) by moving away from 5-30 second file-based chunks in favor of a continuous stream of audio frames.

This phase builds upon the foundation of Phase 11 (Token Streaming) and Phase 11.1 (VAD Pending State), transitioning the architecture from "File-based chunks" to "Continuous Audio Streams."

</domain>

<decisions>
## Implementation Decisions

### [ARCH] Pure Continuous Streams
- **D-01: Session Lifecycle & SimulStreaming Policy:** Move away from creating a new ASR task for every 5-second file. `VoiceToTextProtocol` will be extended to support "Streaming Sessions" using the **LocalAgreement (n=2)** policy.
    - **Master Lifecycle:** `VADStateMachine` (Phase 11.1) remains the master controller for UI bubble lifecycle and ASR Session Start/Stop events.
    - **Stability Check:** Compare the output of the current buffer with the previous one (offset by 500ms). Only "commit" (emit as stable text) the **Longest Common Prefix (LCP)** where both outputs match perfectly.
    - **Forced Prefix Decoding:** Feed the previously "committed" text back into the model as a `prompt` (WhisperKit) or initial tokens (Parakeet) to ensure context continuity.
    - **Teardown:** Sessions must be closed and resources (Neural Engine/Memory) released immediately after a meeting ends (`stopRecording`).
- **D-02: WhisperKit (Pure):** Use `WhisperKit.transcribe(audioArray: ...)` with a **Manual Rolling Audio Buffer (3-5s max)**. 
    - *Note:* `AudioStreamTranscriber` is rejected as it doesn't support direct frame injection without `AVAudioEngine` hijacking.
- **D-03: Parakeet (FluidAudio):** Use `StreamingEouAsrManager` (from `FluidAudio.ASR.Streaming`) which provides specialized streaming with End-of-Utterance (EOU) detection.
    - **K-V Cache Isolation:** Maintain two separate `decoderState` objects (Mic and System) to avoid context mixing while sharing model weights.

### [ARCH] High-Frequency Serial Interleaving
- **D-04: Serial Orchestration:** `TranscriptionQueue` remains the single Serial Actor.
- **D-05: Round-Robin Interleaving:** `MeetingRecorder` will split audio into 200-400ms fragments.
- **D-06: Strict Microphone Priority & Backpressure:** 
    - **Priority:** Microphone fragments have absolute priority.
    - **Backpressure:** Drop the oldest fragments if queue > 2.0s. Target **500ms-800ms total latency**.

### [BEHAVIOR] VAD & Triggers
- **D-07: Stabilized Start:** ASR session starts after ~500ms of stable VAD speech.
- **D-08: Performance First:** True Streaming mode is always enabled.

### [UI/UX] Feedback Loop
- **D-09: Immediate Token Update with Truncation:** Tokens update `MeetingSegment.text` immediately via the `onToken` callback, but implement **Last-Word Truncation**.
    - **Truncation Policy:** If the final word doesn't end with a space or punctuation, hide it from the UI until the next iteration confirms it. This prevents "flickering half-words".
- **D-10: Segment Finalization:** Finished when `VADStateMachine` detects silence or at the 30s cap.

### [SCOPE] SOTA Features
- **In-Scope for 11.2:** LCP Policy, KV-Cache Isolation, Last-Word Truncation.
- **Deferred to Phase 13+:** Context Injection (Meeting Title/Tags), Adaptive VAD Gating (Silence Skipping for Power Save).

</decisions>
